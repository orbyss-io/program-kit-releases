# Architecture and responsibilities

Program Kit is a composition of native Spec Kit components:

| Component | Responsibility |
| --- | --- |
| Governance extension | Product and specification intake, architecture guidance, focused knowledge and native phase checks |
| Building-block extension | Dependency and capability selections, qualified profiles and versioned knowledge |
| .NET extension | Optional .NET engineering guidance, application templates and managed-file tools |
| Governance preset | Appends knowledge to ordinary Spec Kit templates and commands |
| Bundle | Pins the compatible component versions installed together |
| Tooling archive | Complete installed-toolkit inputs for offline updates and recovery |

The installed product-intake skill authors and reviews the founding baseline with
the user. Native Spec Kit phases own subsequent feature delivery. Ordinary plans
and tasks carry agreed human review points. Retired bootstrap workflows, receipts
and checkpoints are historical records and are not resumed as a new founding run.

Program Kit owns reusable engineering guidance and toolkit files. Your application
owns its domain, architecture choices, code, configuration, dependency locks and
authored documents. Optional helpers enforce the contracts of the selected
operation; they do not become an alternative application lifecycle.

Tooling updates replace only recognized owned toolkit files and preserve authored
work. Unknown or customized toolkit files need explicit owner reconciliation.
Application dependency upgrades remain a separate operation.

Public releases distribute readable scripts, templates, references and documentation.
The private repository retains contributor activity, source history and detailed
build evidence. The public repository records distribution changes and publication
approvals; its activity is public.
