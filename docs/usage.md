# First project and everyday use

Open the initialized project in your coding assistant. Start the installed
`speckit.program-kit-governance.product-intake` command or skill. Describe the
product, its users, problems and constraints. Intake gathers actual answers and
authors a founding product baseline, architecture map, architecture decisions and
constitution for human review. Keep unresolved decisions visible; a generated
document is not your approval.

Next, use `speckit.program-kit-governance.specification-intake` for the feature you
want to deliver. Continue through the native Spec Kit specification, plan, tasks
and implementation phases. Program Kit contributes guidance and focused checks to
those phases; it does not run a separate founding workflow or automatically accept
an architecture on your behalf.

The approved product and architecture determine dependency choices. Use
[building-block selection](building-block-selection.md) before adding product
dependencies, and [consumer engineering](consumer-engineering.md) when implementing
or repairing the application. Read only the knowledge relevant to the current
scope; installing Program Kit does not require activating every engineering helper.

Agree review points in ordinary plans and tasks. Review concrete output and real
validation results before accepting a feature. Deterministic checks do not start
coding agents and do not prove that a person accepted the product. Provider account
initialization and any paid work require their own human authority.

Your application, specifications and authored documents belong to you. The kit's
license allows personal and commercial project use and adapted application output;
redistributing Program Kit itself requires separate permission.
